why · the problem

Today, every API grows its own MCP server.

Search team writes one. Pricing team writes one. Inventory team writes one. Each MCP is bespoke code, with bespoke auth, bespoke error handling, bespoke deploys. Multiply by every internal API.

how · the flip

One universal MCP server.
Many APIs behind it.

api_agent is a single server you deploy once. Every API your team needs becomes accessible through the same gateway — just by sending different headers. Add a new API in 30 seconds, not 3 weeks.

how · the magic

Three things happen on every question.

1

Introspect

Agent reads the GraphQL or OpenAPI schema, picks the right operation, generates the call.

2

Land in DuckDB

API returns 10,000 rows. They land in DuckDB. Now you have a real database, even if the API didn't give you one.

3

SQL the rest

Sort top 10. Group by species. Join across endpoints. The agent does in SQL what the API can't do natively.

SELECT species, COUNT(*)
  FROM characters
 WHERE status = 'Alive'
 GROUP BY species
 ORDER BY 2 DESC
 LIMIT 10;
how · it gets smarter

Ask once. Cached forever.

When a query succeeds, the agent extracts the trace into a parameterized recipe. Next time, the same question fires as a direct MCP tool — no LLM reasoning, no token spend, sub-second response.
